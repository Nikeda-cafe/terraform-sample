# Terraform レビュー

## 対象と前提

- **対象**: `.tf` ファイルのみ。レビュー専用のため、コード変更や `apply` は行わない。
- **トリガー**: PR レビュー、コード変更確認、ユーザーがレビューを依頼したとき。

## レビューフロー

1. **変更範囲の把握**: どのサービス（shared / nextjs-app / express-app）・環境（dev / prod）に影響するか確認する。
2. **ベストプラクティスチェック**: 下記チェックリストに沿って確認する。
3. **フィードバック出力**: 重要度別に整理して報告する。

補助として、Terraform MCP の `RunCheckovScan` を実行してセキュリティ・コンプライアンスを確認することを推奨する。

## レビューチェックリスト

### セキュリティ

- [ ] 機密情報（API キー、パスワード、秘密鍵）のハードコードがないか
- [ ] IAM ロール・ポリシーが最小権限の原則に従っているか
- [ ] セキュリティグループのインバウンド/アウトバウンドが過度に広くないか
- [ ] パブリックアクセスが不要なリソースが公開されていないか

### リソース設計

- [ ] リソースに適切なタグ（Name, Environment 等）が付与されているか
- [ ] 命名規則が一貫しているか（prefix + app_name の組み合わせ等）
- [ ] リソースの責務が適切に分離されているか

### モジュール

- [ ] 変数・出力の型と説明が適切か
- [ ] モジュールが環境間で再利用可能な設計か
- [ ] 環境ごとの差分が変数で適切に管理されているか

### 状態管理

- [ ] バックエンド（S3 等）が適切に設定されているか
- [ ] state がサービス・環境ごとに分離されているか

### コスト・可用性

- [ ] prod 環境で冗長構成（マルチAZ等）が考慮されているか
- [ ] 不要なリソースや過剰なスペックがないか

## プロジェクト固有の考慮事項

プロジェクトルートの [docs/overview.md](docs/overview.md) を参照。

- **デプロイ順序**: shared → nextjs-app → express-app（依存関係あり）
- **モジュール共有**: `ecs` モジュールは nextjs-app と express-app で共通。変更時は両方への反映が必要。
- **環境変数**: dev/prod で prefix、ECR 名、desired_count 等が異なる。環境ごとの設定の整合性を確認する。

## フィードバック形式

レビュー結果は次の形式で出力する:

```markdown

### Critical（マージ前に修正必須）
- [該当する項目があれば記載。なければ「なし」]

### Suggestion（改善を推奨）
- [該当する項目があれば記載。なければ「なし」]

### Nice to have（任意）
- [該当する項目があれば記載。なければ「なし」]
```
